Master Setup Guide

End-to-end instructions for flashing and integrating the Radiomaster Pocket controller with an RC car running Raspberry Pi 5.

🆕 Updated for Raspberry Pi 5 — This guide reflects the switch from Jetson Nano to Raspberry Pi 5. The Arduino still connects via USB and enumerates as a joystick at /dev/input/js* — everything works the same way. See the ELRS Version Guide below for notes on using newer firmware versions.

How the System Works

Before following any steps, understand what you are building:

Radiomaster Pocket (TX) Controller — in your hands
ELRS 2.4 GHz RF link  (wireless)
ELRS Receiver RP3 (RX) On the car
SBUS serial @ 115,200 baud  (wired)
Arduino Pro Micro (HID bridge) Translates SBUS → USB joystick
USB  (appears as a joystick to the Pi)
Raspberry Pi 5 Reads joystick at /dev/input/js*

Phase 1 Prerequisites & Hardware

1.1 Required Hardware

  • Radiomaster Pocket controller (TX) — insert both 3.7 V LiPo cells before use
  • RadioMaster RP3 Diversity 2.4 GHz receiver (RX) — mounts on the car
  • Arduino Pro Micro (Leonardo-compatible) — the HID joystick bridge
  • USB-C cable — for flashing the TX (must use the TOP port on the controller)
  • Micro-USB cable — for flashing the Arduino and connecting to the Pi
  • Buck converter — to power the RX (5 V regulated, sufficient current)
⚠️
Warning — LiPo cells
Insert both cells before powering on the controller. The LED illuminates with just one cell, but the radio will NOT transmit. Students frequently miss this.

1.2 Required Software

ToolDetails
ExpressLRS Configuratorv3.3.2 — expresslrs.org/quick-start/installing-configurator/
VSCode + PlatformIOFor flashing the Arduino — install PlatformIO as a VSCode extension

1.3 Wiring

The RX, Arduino, and Raspberry Pi 5 wire together as follows:

  • RX signal pin → Arduino RX pin  (SBUS output from receiver)
  • RX power → Buck converter 5 V  (NOT the Arduino 5 V pin — insufficient current)
  • Arduino → Raspberry Pi 5 via Micro-USB  (enumerates as a HID joystick at /dev/input/js*)
⚠️
Warning — RX Power
The RP3 draws more current than the Arduino 5 V pin can supply. Powering the RX from the Arduino causes it to reset every time it tries to enable WiFi mode. Always use the buck converter.

Phase 2 Flash the Arduino

2.1 Clone the Repository

git clone https://github.com/Triton-AI/ELRSController.git

2.2 Install PlatformIO

  1. Open VSCode and go to Extensions (Ctrl+Shift+X)
  2. Search for PlatformIO IDE and install it
  3. After installation, click the PlatformIO icon in the left sidebar
  4. Choose Open Project and select the cloned ELRSController folder

2.3 Verify platformio.ini

The project should already be configured correctly. Confirm the file contains:

[env:leonardo]
platform  = atmelavr
board     = leonardo
framework = arduino

; build_flags = -DDEBUG_LOG   ← keep this commented out!
⚠️
Do NOT enable DEBUG_LOG
The DEBUG_LOG flag enables Serial output which directly conflicts with the USB HID joystick interface. If enabled, the Raspberry Pi will not see the Arduino as a joystick.

2.4 Upload to the Arduino

  1. Plug the Arduino Pro Micro via Micro-USB
  2. Check the COM port shown in the PlatformIO status bar at the bottom of VSCode
  3. Click the Upload button (→) or press Ctrl+Alt+U
  4. Wait for the SUCCESS message
💡
Upload failing?
Double-press the reset button on the Arduino immediately before clicking Upload. This forces it into bootloader mode and usually resolves port errors.

Phase 3 Flash the Transmitter (TX)

3.1 Prepare the Controller

  1. Insert both LiPo cells and power on the controller
  2. Connect via the TOP USB-C port (not the bottom charging port)
  3. On the controller screen, navigate to the USB dialog using the cylindrical roller (press = select)
  4. Select the third option: USB Serial (VCP) — do not select USB HID or USB Storage

3.2 Configure ExpressLRS Configurator — TX Target

Open ExpressLRS Configurator. Under Firmware Version, select Official Releases → 3.3.2. Do not check Show Pre-releases.

⚠️
Binding phrase is case-sensitive
TritonAI must be entered identically on both the TX and RX — including capitalisation. Any difference and they will never bind.

3.4 Flash the TX

In the Actions section, confirm the serial port shows:

/dev/tty/ACM0 (EdgeTX)     ← Linux / macOS
COM3 (EdgeTX)              ← Windows

Click FLASH and wait for completion. When prompted, download the generated Lua script file.

3.5 Install the Lua Script on the SD Card

  1. Unplug and power off the controller
  2. Remove the SD card from the slot at the bottom
  3. On the SD card, navigate to SCRIPTS/TOOLS/
  4. Copy the Lua file into this folder, replacing any existing file with the same name
  5. Reinstall the SD card and power on
✅
Verify TX firmware
Press SYS → Tools → ExpressLRS on the controller and scroll to the bottom. The firmware version (3.3.2) should be visible.

📡
Why 115,200 baud?
The Arduino code reads SBUS data at 115,200 baud. RCVR_UART_BAUD overrides the ELRS default (420,000 baud for CRSF) so both sides communicate at the same rate. If this is left unchecked, the Arduino will receive garbage data.

4.3 Build the Firmware

Click BUILD (not Flash). Save the generated firmware.bin to a known location.

4.4 Put the RX into WiFi Mode

  1. Power the RX from the buck converter at 5 V
  2. Power on the RX
  3. Wait approximately 60 seconds with no TX powered nearby
  4. The LED will transition: slow blink → very fast blink = WiFi mode active
⚠️
RX resets before WiFi mode
If the RX resets before 60 seconds, it's not getting enough power. Buck converter output should be 5 V with at least 500 mA. Never power the RX from the Arduino 5 V pin.

4.5 Flash the RX via WiFi

  1. Connect your computer to WiFi: SSID: ExpressLRS RX / Password: expresslrs
  2. A captive portal opens automatically — if not, navigate to 10.0.0.1
  3. Upload the firmware.bin file from step 4.3
💡
"Targets Mismatch" dialog — this is expected, click Flash Anyway
You'll see: Current: UNIFIED_ESP32_2400_RX / Uploaded: UNIFIED_ESP8285_2400_RX
This is because the factory firmware used an older chip name (ESP32 → ESP8285). Same hardware. Click Flash Anyway — it is safe.
✅
Re-flashing later
Power-cycle the RX 3–4 times quickly, then wait for fast-blink WiFi mode. In the Configurator, go to Network Devices, select your receiver, and flash.

Phase 5 Bind the Controller to the Car

5.1 Power Both Devices On

Binding is automatic — no button presses required. Both devices were flashed with the same binding phrase, so they find each other on power-up.

  1. Turn on the Radiomaster controller
  2. Power on the RX on the car
  3. Within a few seconds the RX LED changes from blinking to solid — link established
⚠️
RX LED keeps blinking?
Confirm both TX and RX were flashed with: (1) the same ELRS version — 3.3.2, and (2) the exact same binding phrase — TritonAI. A mismatch on either prevents binding.

5.2 Set the RX Output Protocol to SBUS

After binding, tell the RX to output SBUS (which the Arduino reads). Do this once — the setting persists.

  1. On the controller, press SYS → Tools → ExpressLRS
  2. Scroll to the bottom and select Other Devices
  3. Select your RX from the list and wait for it to load
  4. Change the output protocol from CRSF to SBUS and save
  5. Power cycle the RX to apply the change
✅
Verify the link
Return to SYS → Tools → ExpressLRS. Signal strength and packet rate should be displayed, confirming an active RF link.

Phase 6 VESC & Final Configuration

6.1 Enable Kill Switch in VESC Tool

  1. Open VESC Tool and connect to the VESC over USB
  2. Navigate to App Settings → General
  3. Find the Kill Switch Mode setting
  4. Check your relay wiring. On the standard car build, 5 V is Normally Closed (NC) so ground is Normally Open (NO)
  5. Set Kill Switch Mode → ADC2 Low

6.2 Verify End-to-End

  1. Power on the controller
  2. Power on the car (RX + Arduino + VESC)
  3. Confirm RX LED is solid (bound)
  4. On the Raspberry Pi 5, check that the Arduino appears as a joystick:
ls /dev/input/js*
  1. Move the controller sticks and confirm input values change

Troubleshooting Reference

SymptomFix
LiPo cells inserted but controller won't transmit Ensure both cells are seated correctly. The LED lights with even one cell but the radio needs both to operate.
EdgeTX Passthrough port not found in Configurator Controller must be on, plugged into the TOP USB-C port, and set to USB Serial (VCP) — not HID, not Storage.
"Targets Mismatch" warning during RX flash Expected — click Flash Anyway. Factory firmware used a different chip name (ESP32 vs ESP8285). Same hardware.
RX resets before entering WiFi mode RX is underpowered. Use the buck converter at 5 V — never the Arduino 5 V pin.
TX and RX won't bind after flashing Verify: (1) same ELRS version on both — 3.3.2, (2) identical binding phrase — TritonAI. Reflash if unsure.
Controller is bound but car doesn't respond RX output protocol is probably still CRSF. Go to SYS → Tools → ExpressLRS → Other Devices → [your RX] → change to SBUS. Power cycle.
Arduino receives garbage / no data from RX RCVR_UART_BAUD was not set to 115,200. Reflash the RX with RCVR_UART_BAUD checked and value = 115200.
Raspberry Pi doesn't see Arduino as joystick DEBUG_LOG is enabled in platformio.ini — it conflicts with HID. Comment it out and re-flash the Arduino.
Arduino upload fails with port error Double-press the reset button on the Arduino immediately before clicking Upload to force bootloader mode.
Kill switch not working In VESC Tool: App Settings → General → Kill Switch Mode → set to ADC2 Low (5 V normally closed relay wiring).

ELRS Version Guide

As of early 2026, ExpressLRS has released versions up through 3.6.x and 4.0.0 RC. Here's what you need to know for this lab:

Version Compatibility Overview

3.3.2 ✓ Locked for this lab
3.4.x – 3.6.x Compatible with 3.x — upgradeable
4.0.x ⚠ Breaking — NOT compatible with 3.x

Should students use a newer 3.x version?

Recommendation: stick to 3.3.2 for this lab. Here's the reasoning:

  • 3.3.2 is proven, tested, and all the lab instructions match it exactly (Configurator version, Lua script, etc.)
  • All 3.x versions are mutually compatible — so if you do upgrade, both TX and RX must be flashed to the same newer version
  • Later 3.x versions (3.5.x, 3.6.x) include bug fixes and Lua improvements, but nothing that affects SBUS output or UART baud rate for this use case
  • If students want to upgrade, they can safely use any 3.x version (3.4–3.6) — just flash both TX and RX to the same version and re-verify RCVR_UART_BAUD = 115200
⚠️
Do NOT use ELRS v4.x
ELRS version 4 is a major breaking change — it is completely incompatible with v3.x and requires all hardware to be updated simultaneously. It also removes support for some older hardware. Avoid v4 for this lab until the course officially supports it.
💡
Bottom line for students
If your TX or RX already has a newer 3.x version (e.g. 3.5.x or 3.6.x) pre-installed, you can use it — just flash the other device to match. If starting fresh, use 3.3.2 as the guide instructs.
